## ADDED Requirements

### Requirement: HLS 预缓存
对于适用预缓存的 HLS 点播，系统 SHALL 改写 m3u8 列表，把每个分片地址指向本机的分片代理；再由分片代理按预缓存窗口，提前把分片下载到磁盘，供播放器读取。分片代理 MUST 只做透明的字节缓存：分片原样下载、原样存储、原样返回，不解密。播放器看到的效果 MUST 和直连源站一致：源站返回什么错误，就原样返回什么错误；预缓存自身出错时，只能降级为纯转发，不能让视频放不了。

改写规则：

- 只改写以 `#EXTM3U` 开头、带 `#EXT-X-ENDLIST`、至少有一个分片的单码率媒体列表。
- 每个分片 URI 行一对一替换成本机分片代理地址。分片的个数和顺序不变，`#EXT-X-MEDIA-SEQUENCE` 不变。
- `#EXT-X-KEY` 和 `#EXT-X-MAP` 的 URI 按 m3u8 地址补成绝对地址，标签的其余属性不变。
- 除上面两点外，其余行（包括空行和 `#EXT-X-DISCONTINUITY`）逐字保留。
- 请求源站时，带上播放时的原始请求头，每个值都去掉首尾空白。但 `Accept-Encoding`、`Range`、`Host`、`Connection`、`Content-Length` 这几个头（名字不区分大小写）不转发：分片代理总是请求完整分片，传输压缩由 HTTP 客户端自己协商并透明解压。解压后的字节就是源站返回的分片内容，所以仍然算原样下载、原样存储。

调度参数固定如下：

| 参数 | 取值 |
| --- | --- |
| 锚点 | 播放器最近一次请求的分片 |
| 预缓存窗口 | 从锚点开始往后 120 秒（按 `#EXTINF` 时长累加） |
| 回看保留 | 锚点往前 30 秒 |
| 并发下载 | 最多 3 个；被限流后为 1 个 |
| 每个会话的磁盘上限 | 300MB |
| 存储位置 | `<外部缓存目录>/hlscache/` |

同一时间 MUST 只有一个预缓存会话。

#### Scenario: 改写单码率媒体列表
- **WHEN** m3u8 以 `#EXTM3U` 开头，带 `#EXT-X-ENDLIST`，没有 `#EXT-X-STREAM-INF` 和 `#EXT-X-BYTERANGE`，并且有 N 个分片
- **THEN** 改写结果里的 N 个分片 URI 行按原顺序替换成 `http://127.0.0.1:<本地服务实际端口>` 开头的分片代理地址
- **AND** `#EXT-X-MEDIA-SEQUENCE`、`#EXTINF`、`#EXT-X-DISCONTINUITY`、空行等其余行和原文逐字相同

#### Scenario: 密钥和初始化段地址补成绝对地址
- **WHEN** m3u8 里的 `#EXT-X-KEY` 或 `#EXT-X-MAP` 带相对 URI
- **THEN** 改写结果里该 URI 按 m3u8 地址解析成绝对地址
- **AND** `METHOD`、`IV`、`KEYFORMAT`、`BYTERANGE` 等其余属性保持不变
- **AND** 播放器直接向源站请求密钥和初始化段，不经过分片代理

#### Scenario: 不适用的列表不改写
- **WHEN** m3u8 是 master 列表（含 `#EXT-X-STREAM-INF` 或 `#EXT-X-I-FRAME-STREAM-INF`），或者含 `#EXT-X-BYTERANGE`，或者含低延迟 HLS 的 `#EXT-X-PART` 或 `#EXT-X-PRELOAD-HINT`，或者没有 `#EXT-X-ENDLIST`，或者不以 `#EXTM3U` 开头，或者没有任何分片，或者 m3u8 地址不是 `http://` 或 `https://` 开头
- **THEN** 系统不改写该列表，也不开始新的预缓存会话
- **AND** 之前的预缓存会话结束，它的分片从磁盘删除

#### Scenario: 命中预缓存
- **WHEN** 播放器请求的分片已经完整下载到磁盘
- **THEN** 分片代理从磁盘读取该分片，返回 200，不再请求源站

#### Scenario: 未命中预缓存
- **WHEN** 播放器请求的分片不在磁盘上，也没有在下载
- **THEN** 分片代理立即从源站下载该分片，一边下载一边返回给播放器，同时写入磁盘
- **AND** 这次下载不受并发上限和磁盘上限的限制

#### Scenario: 分片文件被外部删除
- **WHEN** 已下载的分片文件被外部删除后，播放器再次请求该分片
- **THEN** 系统按未命中处理，重新从源站下载

#### Scenario: 同一分片的并发请求
- **WHEN** 某个分片正在下载（无论是预缓存还是另一个播放器请求触发的），又有请求要这个分片
- **THEN** 系统不重复向源站请求，后来的请求等待同一次下载，按下载进度拿到数据
- **AND** 所有请求拿到的字节和源站返回的完全一致

#### Scenario: 源站返回 HTTP 错误
- **WHEN** 源站对分片请求返回非 2xx 状态码（如 403、404、503）
- **THEN** 分片代理向播放器返回同一个状态码
- **AND** 该分片不写入磁盘

#### Scenario: 请求源站时去掉的请求头
- **WHEN** 播放时的请求头里有 `Accept-Encoding`、`Range`、`Host`、`Connection` 或 `Content-Length`（名字不区分大小写）
- **THEN** 系统回源时不带这些头，其余请求头去掉首尾空白后照常带上
- **AND** 源站用压缩编码返回时，系统存储和返回的是解压后的分片字节，播放器看不到 `Content-Encoding`

#### Scenario: 预缓存失败的分片不自动重试
- **WHEN** 某个分片的预缓存下载失败（源站返回非 2xx、没有拿到 HTTP 响应，或者长度和 Content-Length 不符）
- **THEN** 本次会话不再自动预缓存这个分片
- **AND** 播放器请求到这个分片时，按未命中处理，从源站重新下载

#### Scenario: 源站无法连接
- **WHEN** 请求源站时没有拿到 HTTP 响应（连接被拒、超时、DNS 失败等）
- **THEN** 分片代理向播放器返回 502

#### Scenario: 磁盘写入失败时降级为纯转发
- **WHEN** 预缓存会话中创建、写入或提交分片文件失败
- **THEN** 本次会话停止所有预缓存下载
- **AND** 之后每个分片请求都直接转发源站的响应，不再读写磁盘，直到会话结束

#### Scenario: 按窗口预缓存
- **WHEN** 播放器请求了第 k 个分片
- **THEN** 第 k 个分片成为锚点
- **AND** 系统按顺序下载开始时间距锚点不足 120 秒、还没有下载的分片，同时最多 3 个下载

#### Scenario: 暂停时填满窗口后停止
- **WHEN** 播放器暂停，不再请求新分片
- **THEN** 系统继续下载，直到窗口内的分片都已下载，然后停止

#### Scenario: 回看淘汰
- **WHEN** 锚点前移到第 k 个分片
- **THEN** 开始时间比锚点早 30 秒以上的分片从磁盘删除
- **AND** 开始时间比锚点早 30 秒以内的分片保留，再次请求时直接命中

#### Scenario: 跳转
- **WHEN** 播放器请求的分片既不是当前锚点，也不是锚点的下一个分片
- **THEN** 系统按新锚点重新计算窗口
- **AND** 取消新窗口之外正在进行的预缓存下载，删除新窗口和回看范围之外的已下载分片
- **AND** 从新锚点开始预缓存

#### Scenario: 达到磁盘上限
- **WHEN** 本次会话已存储的分片，加上正在下载的分片预计大小，再加上下一个分片的预计大小，会超过 300MB
- **THEN** 系统先删除锚点之前的回看分片来腾出空间
- **AND** 腾出空间后仍然超过时，不再开始新的预缓存下载，窗口相当于缩短到已下载的位置；锚点前移、释放出空间后再继续

#### Scenario: 被限流时降为单线程
- **WHEN** 同一会话里累计 3 次请求源站时遇到 429、503、403 或连接被拒
- **THEN** 本次会话的并发下载数降到 1，播放器请求触发的下载也计入这个并发数
- **AND** 本次会话内不再恢复到 3 个

#### Scenario: 同一 m3u8 地址复用已下载的分片
- **WHEN** 开始新的预缓存会话时，m3u8 地址和上一个会话相同
- **THEN** 新会话复用上一个会话已下载的分片，命中的分片不再请求源站
- **AND** 上一个会话正在进行的下载被取消，上一个会话的分片代理地址失效

#### Scenario: 不同 m3u8 地址或离开播放页时清空
- **WHEN** 开始新的预缓存会话时 m3u8 地址和上一个会话不同，或者离开播放页时结束会话
- **THEN** 上一个会话的下载全部取消，它的分片从磁盘删除

#### Scenario: 只结束自己建的会话
- **WHEN** 播放页结束会话时说明「结束我建的会话」，而当前会话是后来另一个播放页建的（比如旧页面的销毁晚于新页面开始播放）
- **THEN** 当前会话不受影响，继续预缓存，它的代理地址仍然有效
- **AND** 只有当前会话正是这个播放页建的时，才按「离开播放页」结束它
- **AND** 按「结束我建的会话」请求、却没有给出播放页标识时，什么都不结束（无条件结束会话的请求不受这条限制）

#### Scenario: 请求已失效的会话
- **WHEN** 播放器用已结束或已被替换的会话的分片代理地址请求分片
- **THEN** 分片代理返回 410，不请求源站
