## ADDED Requirements

### Requirement: 预缓存的作用范围
`设置 → 预缓存` 开启时，全屏播放页和详情页小窗播放器 SHALL 对经过普通点播流程的 HLS 播放启用预缓存（改写规则、调度与会话复用见「HLS 预缓存」）：系统先下载 m3u8；如果它是只含一个子列表的主列表，再下载一次子列表；然后把最终要播的那份列表交给预缓存改写。交给改写的内容规则如下：

| 广告过滤 | 净化结果 | 交给改写的内容 |
| --- | --- | --- |
| 开启 | 成功 | 净化后的内容 |
| 开启 | 失败（无法净化） | 原文 |
| 关闭 | 不净化 | 原文 |

改写成功时，播放器 MUST 通过本地服务的 `/m3u8` 地址播放改写后的列表；该列表不适用预缓存时，系统 MUST 按未开启预缓存时的逻辑播放（广告过滤开启且净化成功时播放净化后的列表，否则播放原地址），不能因为预缓存导致视频放不了。

以下播放 MUST NOT 使用预缓存，交给播放器的地址 MUST 和未开启预缓存时完全一致：

- `设置 → 预缓存` 关闭（默认）；
- 当前内核是外部播放器（MX、Reex、Kodi）；
- 直播；
- 「特殊链接直接播放」列出的链接：存储空间里的视频（`tvbox-drive://`）、迅雷类链接（磁力、`thunder://`、`ed2k://`、`.torrent`、`ftp://`）、荐片链接（`xg://`、`xgplay://`、`tvbox-xg:`）、分段 mp4；
- 地址里既不含 `.m3u8`、也不含 `://127.0.0.1/` 的普通直链。

预缓存会话 MUST 在离开播放页时结束。后台播放、画中画、详情页小窗与全屏之间切换 MUST NOT 结束会话。开始播放一个不使用预缓存的内容时，系统 MUST 结束上一个预缓存会话。

#### Scenario: 开关关闭时不改写
- **WHEN** `设置 → 预缓存` 为关闭（包括从未修改过），用户播放一个 HLS 点播
- **THEN** 系统不改写 m3u8，不开始预缓存会话
- **AND** 是否下载 m3u8、是否去广告、交给播放器的地址都和没有预缓存功能时完全一致

#### Scenario: 开关打开时两个播放入口都走预缓存
- **WHEN** `设置 → 预缓存` 开启，用户在全屏播放页或详情页小窗里播放一个适用预缓存的 HLS 点播（带 `#EXT-X-ENDLIST` 的单码率媒体列表）
- **THEN** 播放器通过 `http://127.0.0.1:<本地服务实际端口>/m3u8` 播放
- **AND** 该列表里的每个分片地址都指向本机的分片代理

#### Scenario: 跟随一次子列表后改写子列表
- **WHEN** `设置 → 预缓存` 开启，下载到的 m3u8 是只含一个子列表的主列表
- **THEN** 系统下载该子列表，并以子列表的地址作为 m3u8 地址交给预缓存改写

#### Scenario: 去广告关闭时也改写
- **WHEN** `设置 → 预缓存` 开启，`设置 → 广告过滤` 关闭，用户播放地址含 `.m3u8` 的点播
- **THEN** 系统先下载 m3u8，再把原文交给预缓存改写
- **AND** 改写成功时播放器通过本地 `/m3u8` 播放，列表里的广告分片不做删除

#### Scenario: 净化失败时也改写
- **WHEN** `设置 → 预缓存` 和 `设置 → 广告过滤` 都开启，m3u8 无法净化
- **THEN** 系统把 m3u8 原文交给预缓存改写
- **AND** 改写成功时播放器通过本地 `/m3u8` 播放

#### Scenario: 净化成功时改写净化后的内容
- **WHEN** `设置 → 预缓存` 和 `设置 → 广告过滤` 都开启，m3u8 净化成功
- **THEN** 系统把净化后的内容交给预缓存改写，广告分片不会出现在改写后的列表里

#### Scenario: 列表不适用时按原逻辑播放
- **WHEN** `设置 → 预缓存` 开启，最终要播的列表不适用预缓存（如多码率主列表、带 `#EXT-X-BYTERANGE`、没有 `#EXT-X-ENDLIST`），或者下载 m3u8 失败
- **THEN** 广告过滤开启且净化成功时，播放器播放净化后的本地 `/m3u8`
- **AND** 其余情况播放器播放原地址（跟随过子列表时为子列表地址；下载失败时为最初的地址）

#### Scenario: 外部播放器不改写
- **WHEN** `设置 → 预缓存` 开启，当前内核是 MX、Reex 或 Kodi，用户开始播放
- **THEN** 系统不改写 m3u8，交给外部播放器的地址和请求头和未开启预缓存时完全一致
- **AND** 上一个预缓存会话结束

#### Scenario: 直播等特殊链接不走预缓存
- **WHEN** `设置 → 预缓存` 开启，用户观看直播，或者播放存储空间里的视频、迅雷类链接、荐片链接、分段 mp4
- **THEN** 系统不改写，不开始预缓存会话，交给播放器的地址和未开启预缓存时完全一致

#### Scenario: 普通直链不下载 m3u8
- **WHEN** `设置 → 预缓存` 开启，`设置 → 广告过滤` 关闭，播放地址既不含 `.m3u8` 也不含 `://127.0.0.1/`
- **THEN** 系统直接播放原地址，不下载、不改写

#### Scenario: 切集、重播与切内核重试重新改写
- **WHEN** `设置 → 预缓存` 开启，用户切到上一集或下一集、点重播，或者播放出错后系统切换内核自动重试
- **THEN** 系统重新走一遍下载与改写，由新的改写决定复用还是清空上一个会话的分片
- **AND** 新的播放内容不使用预缓存时，上一个会话结束

#### Scenario: 离开播放页时结束会话
- **WHEN** 用户从全屏播放页返回，或者离开带小窗播放器的详情页
- **THEN** 当前预缓存会话结束，下载全部取消，它的分片从磁盘删除

#### Scenario: 旧页面晚到的销毁不影响新页面的会话
- **WHEN** 系统先关闭旧的详情页、再打开新的详情页（后台设置为「画中画」时打开另一部影片的详情页，或者收到推送打开详情页），新页面已经开始预缓存之后，旧页面才完成销毁
- **THEN** 新页面的预缓存会话继续，播放器仍然能正常拿到它的分片
- **AND** 旧页面销毁时只结束它自己开始的预缓存会话

#### Scenario: 后台播放、画中画不结束会话
- **WHEN** 后台设置为「开启」时用户退到后台继续播放，或者后台设置为「画中画」时用户按 Home 键进入画中画
- **THEN** 预缓存会话继续，回到播放页或在画中画里继续播放时仍然使用已下载的分片

#### Scenario: 关闭画中画小窗时结束会话
- **WHEN** 全屏播放页处于画中画，用户关闭画中画小窗，播放器随之释放
- **THEN** 当前预缓存会话结束

#### Scenario: App 启动时清空预缓存目录
- **WHEN** App 启动，外部缓存目录下的 `hlscache/` 里留有上一次进程的会话目录（比如进程被杀，会话没有正常结束）
- **THEN** 启动过程中 `hlscache/` 被清空，之后开始的预缓存会话不会用到旧的分片
- **AND** 旧内容的删除在后台进行，不在主线程逐个删除文件，App 启动不因此卡住
- **AND** 以前几次启动没有删完的旧内容也一起删除

#### Scenario: 详情页小窗照常预缓存
- **WHEN** `设置 → 预缓存` 和 `设置 → 窗口预览` 都开启，用户进入详情页，小窗自动开始播放 HLS 点播
- **THEN** 小窗播放同样走预缓存
- **AND** 小窗与全屏之间切换时，会话不结束，播放不重新改写
